# Деплой бота «Marina Twin»

## Что нужно получить заранее

1. **Токен Telegram-бота.** В Telegram напишите @BotFather → `/newbot` → задайте имя и username (например `MarinaTwin_Bot`) → получите токен вида `123456:AAExxxxx`.
2. **Отключить Privacy Mode для группового сбора задач.** По умолчанию Telegram-боты видят в группах только команды и сообщения, где их явно упомянули — обычную переписку боту не показывают. Чтобы Marina Twin могла молча читать всю переписку и собирать задачи, у @BotFather: `/mypbot` (или сразу `/setprivacy`) → выбрать бота → **Disable**. Это нужно сделать **до** того, как добавите бота в группы (если бот уже добавлен — удалите и добавьте заново после отключения).
3. **Ключ Anthropic API.** В консоли platform.claude.com создайте API-ключ (раздел API Keys). На счету должен быть баланс — оплата идёт по фактическому использованию.
4. **Свой Telegram user_id** (чтобы бот в личке отвечал только сотрудникам) — напишите @userinfobot, он пришлёт ваш id. Соберите id всех сотрудников, кому можно писать Marina Twin в личку. Это ограничение не касается групп — в группу бота просто добавляют как участника.
5. **(Опционально, для сбора задач в ClickUp)** — API-токен и ID списка, см. раздел «ClickUp» ниже. Без них групповой сбор всё равно работает (Marina Twin копит переписку в своей базе), просто задачи никуда не выгружаются, пока токен не появится — это можно донастроить в любой момент позже, не переделывая деплой.

## Вариант 1 — Railway (проще всего, рекомендую для старта)

Актуально на 2026 год, проверено по официальной документации Railway.

1. Зарегистрируйтесь на railway.com (или railway.app — тот же сервис). Бесплатный план (Free) даёт стартовый кредит и подходит, чтобы проверить, что всё работает; для постоянной работы без пауз обычно переходят на план Hobby ($5/мес, включает $5/мес расходного кредита) — привязывать карту для этого не обязательно сразу, Railway попросит это только когда/если понадобится.
2. Залейте папку `marina_twin_bot` (содержимое этого архива) в свой репозиторий на GitHub — Railway разворачивает именно из репозитория.
3. В Railway: **New Project → Deploy from GitHub repo** → выберите репозиторий.
4. Откройте созданный сервис → вкладка **Variables** → добавьте переменные окружения:
   - `TELEGRAM_BOT_TOKEN`
   - `ANTHROPIC_API_KEY`
   - `MARINATWIN_ALLOWED_USER_IDS` (через запятую, id сотрудников для личных сообщений)
   - опционально `MARINATWIN_MODEL`, `MARINATWIN_MAX_TOKENS`
   - опционально `CLICKUP_API_TOKEN`, `CLICKUP_LIST_ID`, `CLICKUP_FLUSH_INTERVAL_MINUTES` (см. раздел ниже)
5. Railway сам увидит `Dockerfile` в репозитории и соберёт контейнер — отдельно ничего настраивать не нужно. У бота нет HTTP-порта (это фоновый процесс, а не веб-сервис) — это нормально, Railway не требует health-check для таких сервисов.
6. **Volume для истории чатов и накопленных сообщений групп** — иначе при каждом передеплое (например, когда вы обновите код) всё обнулится. В сервисе: правой кнопкой на сервис или через командную палитру → **Volume** → создайте том и примонтируйте на путь `/app/data`.
7. После деплоя откройте бота в Telegram и напишите `/start` в личке — должен поздороваться.

## Вариант 2 — любой VPS с Docker

```bash
# на сервере
git clone <ваш-репозиторий> marina_twin_bot
cd marina_twin_bot
cp .env.example .env
nano .env   # впишите токены

docker build -t marina-twin-bot .
docker run -d --name marina-twin \
  --env-file .env \
  -v $(pwd)/data:/app/data \
  --restart unless-stopped \
  marina-twin-bot

docker logs -f marina-twin   # проверить, что стартовал без ошибок
```

`--restart unless-stopped` — бот поднимется заново после перезагрузки сервера.

## Вариант 3 — без Docker, просто systemd

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и заполнить
```

Дальше — юнит systemd, который читает `.env` и держит `python bot.py` живым (спросите, если нужен готовый файл юнита — соберу).

## ClickUp: сбор задач из групповых чатов, по проектам

Как это работает: добавьте Marina Twin в любой групповой чат сотрудников (не забудьте про Privacy Mode выше). Она молча читает переписку, ничего не отвечает и не участвует в разговоре — кроме двух случаев ниже (закрепление проекта и обращение по имени).

Задачи разложены по проектам, у каждого свой список ClickUp:

| Проект | Команда | Фраза-привязка в чате | Список ClickUp |
|---|---|---|---|
| Atlas | `/tasksatlas` | «...эта груп­па про/для задач Atlas/Атлас...» | папка «Atlas Marina Twin» |
| Алтын | `/tasksaltyn` | «...эта груп­па про/для задач Altyn/Алтын...» | папка «Altyn Marina Twin» |
| BestSwift | `/tasksbs` | «...эта груп­па про/для задач Bestswift/BS...» | папка «BestSwift Marina Twin» |
| — (авто) | нет | — | папка «Разобрать Marina Twin» |

### Как закрепить чат за проектом

Два равнозначных способа — что удобнее:

1. **Фразой в обычном сообщении** — напишите в группе что-то вроде «это группа про задачи Altyn» (подойдёт и «Алтын», и в любом падеже/порядке слов, главное — упомянуть в одном сообщении и слово «групп-», и название/аббревиатуру проекта). Marina Twin ответит подтверждением и запомнит привязку.
2. **Командой** — `/tasksatlas`, `/tasksaltyn` или `/tasksbs` прямо в группе: сразу выгружает накопленное в список этого проекта и заодно закрепляет проект за чатом.

После любого из двух способов чат автоматически выгружается по расписанию (по умолчанию каждые 5 минут, `CLICKUP_FLUSH_INTERVAL_MINUTES`), без повторных действий. Чтобы перекинуть чат на другой проект — просто повторите любой из способов с другим проектом, привязка обновится.

**Группа, где обсуждают всё подряд (несколько проектов в одном чате)** — просто не привязывайте её ни к одному проекту. Такой чат тоже выгружается автоматически каждые `CLICKUP_FLUSH_INTERVAL_MINUTES` минут, но каждая задача разбирается по отдельности: если по контексту понятно, к какому проекту она относится — уходит в соответствующий список; если нет — падает в папку **«Разобрать Marina Twin»**, чтобы ничего не потерялось и не попало не туда наугад.

### Обращение к «Марине» в группе

Если кто-то в группе упоминает бота (`@username`), отвечает (reply) на её сообщение, или просто пишет «Марина» — Marina Twin вежливо отвечает, что сейчас уточнит и вернётся, и пересылает вопрос **владелице в личку** (переменная `MARINATWIN_OWNER_USER_ID`, см. ниже). Дальше: владелица отвечает боту в личке обычным сообщением (именно следующим по времени — оно считается ответом на этот вопрос), Marina Twin красиво перефразирует ответ от её лица и публикует его в исходной группе — коллеги видят обычный ответ «Марины», не зная о пересылке в личку.

### Получить токен, ID списков и ID владелицы

1. **API-токен**: в ClickUp — аватар в правом верхнем углу → **Settings → Apps** → раздел «API Token» → сгенерировать/скопировать. Токен вида `pk_...`, не имеет срока действия. Прямая ссылка: `app.clickup.com/settings/apps`.
2. **ID списка (List)** для каждого проекта: откройте в вебе ClickUp нужный список → посмотрите в адресной строке браузера, там будет что-то вроде `.../v/li/901234567890` — цифры после `li/` и есть ID.
3. Впишите значения в переменные окружения: `CLICKUP_API_TOKEN`, `CLICKUP_LIST_ATLAS`, `CLICKUP_LIST_ALTYN`, `CLICKUP_LIST_BESTSWIFT`, `CLICKUP_LIST_UNSORTED` — на Railway это вкладка Variables, для VPS/systemd — файл `.env`. Можно задать не все — привязка к незаданному проекту просто ответит, что список ещё не настроен.
4. **`MARINATWIN_OWNER_USER_ID`** — Telegram user_id владелицы (через @userinfobot), нужен для эскалации вопросов из групп. Если уже задан ровно один `MARINATWIN_ALLOWED_USER_IDS` — можно не дублировать, возьмётся автоматически.

### Как проверить, что подключено верно

После деплоя с заданными переменными в логах бота при старте должно быть: `ClickUp-интеграция включена (проекты: atlas, altyn, bestswift, unsorted), автовыгрузка каждые 5 мин.` Дальше:
- Напишите в тестовой группе «это группа про задачи Atlas» — должен прийти ответ-подтверждение.
- Напишите что-то вроде «Маш, до пятницы нужно созвониться с банком по счёту» и вызовите `/tasksatlas` — должна прийти задача в список Atlas.
- Напишите в группе «Марина, а как у нас с лимитами по счёту?» — бот должен ответить, что сейчас вернётся, а владелице должно прийти сообщение в личку с этим вопросом. Ответьте на него — ответ должен прийти в исходную группу уже перефразированным.

### Ограничения текущей версии (честно)

- Задачи создаются без назначения исполнителя в ClickUp (нет сопоставления Telegram-пользователь → ClickUp-пользователь) — если в переписке явно назван ответственный, это попадёт текстом в описание задачи, но не в поле "Assignee".
- Извлечение задач — отдельный, независимый от юридической персоны вызов Claude без загрузки полной базы знаний (она была бы избыточной и дорогой для этой задачи) — качество зависит от того, насколько явно в переписке сформулировано поручение. Классификация задач по проекту в "смешанных" чатах — по тому же принципу: неоднозначное уходит в «Разобрать», а не гадается наугад.
- Эскалация вопросов работает по очереди FIFO: если владелице пришло несколько вопросов из разных групп подряд, её **следующее** сообщение боту в личке ответит на самый старый неотвеченный вопрос, а не обязательно на тот, который она имеет в виду. Если вопросов накопилось несколько — удобнее отвечать на них по очереди, один за другим.
- Привязка «чат → проект» одна на весь чат (для чатов, которые вы явно привязали): если в одном Telegram-чате реально обсуждают несколько проектов вперемешку, лучше не привязывать его ни к одному проекту — тогда включится классификация по отдельным задачам (см. выше).
- Если группу конвертируют в супергруппу (Telegram иногда делает это автоматически при росте числа участников), у неё меняется chat_id — накопленный, но ещё не выгруженный буфер для старого id может «зависнуть», а привязка к проекту для нового id пропадёт. Это редкий случай; если случится — просто повторите привязку (фразой или командой) заново после конвертации.

## Проверка после деплоя

- `/start` в личке — должен поздороваться.
- Задайте вопрос про Россию — ответ из RU_LAW.
- Задайте вопрос про Казахстан — должен явно опираться на казахстанский модуль (упомянет местные акты).
- `/reset` в личке — должен сбросить историю разговора.
- В группе (после отключения Privacy Mode) — напишите что-то, бот не должен отвечать ничего. Позовите `/tasks` — должен либо создать задачи, либо сказать, что новых не нашёл.
- Посмотрите логи (`docker logs` или консоль Railway) — там пишется usage по каждому запросу (input/cache_write/cache_read/output), по этим цифрам легко проверить, что кэш реально работает: после первого сообщения в чате `cache_read` должен резко расти, а `input`/`cache_write` — падать почти до нуля на следующих сообщениях.

## Стоимость (справочно)

**Личка (Anthropic).** При активном использовании (сообщения идут чаще, чем раз в час) большинство запросов будет кэш-хитом — это около 7-10 центов за сообщение на текущей базе. Холодный старт разговора (первое сообщение за час) — примерно 1-1.5 доллара из-за записи в кэш ~400-450 тысяч токенов базы.

**Группы (Anthropic).** Извлечение задач — отдельный, лёгкий вызов без базы знаний, стоит копейки за выгрузку (доли цента — единицы центов, в зависимости от объёма накопленной переписки).

**Railway.** Обычно единицы долларов в месяц на фоновый процесс такого размера — основные расходы будут в Anthropic API, не в хостинге.

**ClickUp.** Создание задач через API бесплатно в рамках вашего тарифа ClickUp (лимиты — по вашему плану ClickUp, не связаны с этим ботом).
